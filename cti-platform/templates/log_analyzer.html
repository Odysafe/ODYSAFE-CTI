🔍 How Log Analysis Works

1. Pattern Matching

Each log event is scanned against 200+ regex patterns covering all 14 MITRE ATT&CK tactics. Patterns cover endpoint activity (Windows, Linux), network events (firewall, proxy, DNS), web application logs (Apache, Nginx, IIS), Active Directory events, and cloud logs (AWS CloudTrail, Azure Activity). Keywords include "powershell", "mimikatz", "lsass", "registry run key", "lateral movement", "dns tunneling", "vssadmin", "wbadmin". A match does not confirm a compromise, it signals an area requiring manual investigation.

2. Field Extraction

The system attempts to extract the following fields from each log line:
• timestamp: Parsed from the log line itself (ISO 8601, Syslog, Windows Event format). Falls back to upload time if no timestamp is found in the line.
• source: Originating system or log type (firewall, sysmon, webserver, AD, cloud...)
• description: The full raw log message used for pattern matching
• host: Hostname or IP of the machine involved, when present

3. Signal Strength

Indicates how strongly a log event matches a known attack pattern:

• 🔴 High Priority - ≥ 80%: strong multi-keyword match on a high-severity tactic
• 🟠 Medium Priority - 50-79%: partial match or lower-severity tactic
• 🟡 Low Priority - < 50%: weak signal, single keyword match

Signal strength reflects pattern confidence only, not the actual severity of the incident.

4. Timeline Building

Matched events are sorted chronologically using the timestamp extracted from each log line, then grouped by MITRE ATT&CK tactic following the Cyber Kill Chain order: Initial Access, Execution, Persistence, Privilege Escalation, Defense Evasion, Credential Access, Discovery, Lateral Movement, Collection, Exfiltration, Command and Control, Impact. Tactics with no events detected are shown as Blind Zones, their absence does not confirm the attack skipped that phase.

📋 Supported Formats
CSV: SIEM exports, Windows Event exports, spreadsheet logs with headers
JSON: AWS CloudTrail, Azure Activity Logs, API logs, structured SIEM events
TXT/LOG: Syslog (RFC 3164/5424), Windows application logs, Apache/Nginx/IIS access logs, firewall logs, plain text
XML: Windows Event Log exports (.xml), structured event formats
📤 Output
• Attack timeline ordered by real log timestamps, grouped by MITRE tactic
• Technique detection cards with event counts and signal strength distribution
• Export to JSON or CSV
• Blind Zone indicators for undetected tactics, with contextual warning message
• Global disclaimer banner reminding that results require manual analyst review
⚠️ Automatic analysis — Results are indicative only. Patterns are keyword-based; a non-detection does not imply the absence of a threat. Manual review is always required to confirm findings. Source analyzed: uploaded log file only.
